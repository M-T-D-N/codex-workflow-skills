# 작업 진행 기록

재개·인계·진척 판단이 필요한 다단계·반복·장시간 작업에 적용한다. 현재 적용되는 완료·집계·권한 규칙을 따르며, 단순 질의와 즉시 끝나는 작업에는 응답·기존 로그로 충분하다. 이 절차가 별도 Goal 생성이나 새 승인 단계를 요구하지 않는다.

## 시작과 계량

- 대상 식별자·입력 버전·단계별로 중복 없이 집계하고 재시도·도구 호출은 완료 건수에 더하지 않는다. 수집·저장·검토·검증·반영을 구분하며, 비율은 같은 범위·시점·단계의 확인된 분모로만 계산한다.
- 본격 실행 전에 사용자 결과, 현재 범위·입력 기준, 완료 조건, 작업 단위와 다음 체크포인트를 정하고 간단히 알린다. 계수 가능한 작업은 대상별 단계와 완료 수를, 조사·설계·수정은 답해야 할 질문이나 확인 가능한 수용 조건을 사용한다. 쉬운 항목 수나 도구 호출 수로 실제 결과를 대신하지 않는다.
- 전체량이 미정이면 탐색 경계·종료 조건과 현재 발견한 대상·미확인 범위를 먼저 잡는다. 미확인 범위를 남긴 채 진행 가능한 작업을 이어가고 새 근거에 따라 범위를 갱신한다. 완벽한 전수조사를 실행의 선행 조건으로 만들거나 발견한 일부를 전체로 계산하지 않는다.

## 작업 기록

- 읽기 전용 작업에서는 기록을 응답·기존 로그에 남기고 파일·DB를 갱신하지 않는다. 기록이나 체크포인트는 중단·재개 권한을 바꾸지 않는다.
- 기존 DB·manifest·작업 상태 문서 중 소유자와 대상이 맞는 기록을 우선 사용한다. 승인된 쓰기 작업에서 기존 결과·로그만으로 재개하기 어렵고 적합한 기록이 없을 때만 소유 경로에 최소 기록 하나를 둔다. 필수 필드명·파일 형식·새 저장 체계를 만들지 않는다.
- 기록에는 현재 목표·범위·완료 조건과 입력 기준, 대상·단계별 상태, 완료 결과와 원본 근거, 미완료·실패·미확인·제외 이유, 판단에 중요한 가정·결정과 다음 행동을 유지한다. 실행 중 작업이 있으면 기존 도구·실행 ID와 확인 위치를 연결한다. 계획·추정·실행 사실을 구분하고, 원본을 복제하지 말고 근거 위치를 남긴다.
- 현재 상태를 갱신하고 판단이 달라진 이유만 간결히 보존한다. 동일 내용의 보고서·인계문·등록부를 늘리거나 원시 대화·도구 출력을 기록에 누적하지 않는다. 이 기록은 실제 파일·실행 상태의 백업이나 복구 수단을 대신하지 않는다.

## 갱신과 재개

- 완료된 결과 묶음, 중요한 실패·결정·요구 변경, 작업 방향 전환이나 인계 시 기록을 갱신한다. 장시간 대기 전에는 실행 ID와 다음 확인 위치를 남긴다. 묶음 크기는 중단 시 잃는 작업량과 중복 실행 위험에 맞추며, 매 클릭·도구 호출마다 쓰거나 압축 안내·대화 종료까지 미루지 않는다.
- 사용자 요구가 변경·추가되면 변경 내용과 범위·완료 조건에 대한 영향을 반영한다. 유효한 기존 결과·근거는 재사용하고 영향받은 항목만 재검증 대상으로 돌린다. 명시적으로 대체·취소되지 않은 미완료 요구는 유지하며, 제외·대체된 항목을 완료로 세지 않는다.
- 압축·중단·인계 후에는 최신 기록에서 현재 요구와 관련된 범위·근거·미완료 항목을 확인한다. 기록과 실제 상태가 충돌하거나 실행 여부가 불확실하면 해당 원본·대상 상태를 대조해 바로잡은 뒤 의존 작업을 이어간다. 특히 결과가 불명확한 외부 변경은 확인 없이 재실행하지 않는다. 유효한 완료 작업을 전부 다시 조사하지 않는다.
- 각 조사·수정이 해결할 미완료 조건을 정하고 진행한다. 같은 불확실성이 반복되거나 범위만 늘면 체크포인트에서 접근법·잔여 범위를 재평가하고 필수 완료 조건과 선택적 개선을 구분한다. 다음 실행을 정할 수 있을 만큼 확인되면 진행하며, 현재 완료 조건 충족 후 새 과제를 계속 만들지 않는다.

## 기록 실패와 중단

- 기록 저장이 실패하면 결과와 실패 사실을 허용된 응답·기존 로그에 남기고, 손실·중복 실행 위험이 없는 독립 작업은 계속한다. 필요한 원본 근거를 보존할 수 없는 의존 단계만 보류하고 정확한 저장 범위를 복구한다. 저장 성공을 주장하거나 다른 소유 경로·권한 우회로 기록하지 않는다.
- 기록 형식·문서 완성을 별도 실행·승인 조건으로 만들지 않는다. 사용자의 즉시 중단은 우선하며 기록을 위해 실행을 연장하지 않는다. 현재 단위를 마치고 대기하라는 요청은 그 단위의 필요한 기록까지 갱신한 뒤 대기하고 다음 단위를 시작하지 않는다.
