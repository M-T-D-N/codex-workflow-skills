# Ordinary app workers and file delivery

Use this lane only when the user authorizes new app tasks and the host exposes the needed task tools. Preserve the selected model and effort. Native capacity, permission or scheduling limits do not authorize creating another app task.

## Dispatch

Use the exposed task-creation tool with its documented model and reasoning/thinking arguments. Where the host exposes `create_thread`, `list_projects` and ordinary local project tasks, use the returned project ID and `environment.type=local` for that authorized environment. Do not substitute a worktree chat, fork, resume or native child. Do not silently replace unsupported settings or change Main's model. Follow current host capacity limits; start another worker only for a useful independent unit.

Include the outcome and acceptance, exact source/baseline references, required authority reads, allowed file scope, preserved contracts, an owned output location and the [shared acceptance contract](handoff-and-results.md#handoff-and-scheduling). Code writes need an executable acceptance command; writing, visual and UI work need an appropriate saved/rendered-artifact check. Workers own implementation, relevant checks and ordinary local fixes; no redelegation.

For a long operating document mixed with history, include exact start/end headings and a tested read command that outputs only the relevant section. Resolve headings from current source rather than fixing historical line numbers, and preserve required authority reads. Do not copy the whole parent conversation or old pilot answers.

Record the returned exact thread ID and associate its output location with that owner. Use the current host's supported thread metadata to resolve missing identity; never borrow another task's identity. Explicit permissions still apply to source, output and temporary/test paths. Approval waiting is not failure.

## File return and acceptance

A file-delivery worker returns its changed/additional files with their original relative paths and extensions inside its assigned output location, plus actual paths, changes, checks and unresolved issues in its final response. Keep temporary files and test logs outside that delivery file set. Do not serialize entire source files into message JSON.

Retrieve actual files before treating terse or malformed final text as implementation failure. Match owner identity, allowed paths and the current source baseline. Reject escaping or ambiguous paths and file links that can escape the assigned ownership boundary. A stale baseline is a conflict, never permission to overwrite source. Use existing host or repository checks; no private helper, fixed contract-file schema or new intake framework is required.

File intake establishes readiness for review, not acceptance. Main inspects the actual content/diff and independently grounded verification evidence under the shared contract. Recheck a mutable source baseline immediately before integration. Distinguish missing files, scope violations, changed baselines, identity mismatches, tool errors, functional failure and formatting-only final-message issues. Do not auto-repair content to hide failure.

Use supported settings metadata when available to compare requested and observed model/effort. Prompt text and a worker's self-report are insufficient proof; unavailable evidence stays unknown. Apply the shared [correction and takeover rules](handoff-and-results.md#correction-or-takeover) after the current execution ends and its effects are attributed.

## Completion and measurement

Use exact thread IDs and supported cursors for bounded waits; where available, prefer `wait_threads` and use `read_thread` only for missing detail. Timeout, silence and approval delay are not execution failure. Do not send progress-only prompts or duplicate pending work.

An ordinary app task has no native parent agent. It reports through its own normal commentary/final and actual artifacts for Main's exact-ID retrieval; do not send native collaboration messages to a guessed `/root` handle or another task.

Measure only from existing available usage and execution evidence. Include Main preparation/review/rework and all worker corrections or discarded attempts; preserve missing portions as unknown. Distinguish the actual wall interval from summed worker durations and avoid double-counting cumulative snapshots. No dashboard or extra scorer is required. Follow the shared [measurement guidance](handoff-and-results.md#measure-effects).

Archive finished app tasks only when the user authorized that lifecycle and artifacts needed for acceptance, recovery or handoff have been retrieved. Archiving is not deletion.
