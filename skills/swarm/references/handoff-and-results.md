# Handoff, scheduling and acceptance

Read before dispatch and reuse for result acceptance. This is the existing Swarm execution contract, not an additional gate.

## Handoff and scheduling

A packet names the actual parent agent handle, project and host task/session/request identity (as available), exact repository/workspace and starting state, pre-existing changes to preserve, user outcome and material exceptions, selected native worker model/effort with a brief workload rationale, owned files or a narrow feature boundary with exclusions, source locations, acceptance behavior and known commands, and uncertainties to return rather than guess. Native workers may choose ordinary implementation details and discover suitable existing verification within that boundary. Qwen requires its existing public invocation, working directory, necessary source/owned paths, expected output and cheap acceptance check before dispatch. Write tasks need an executable acceptance command; read-only tasks use the existing read-only path and source/schema checks. Shell syntax requires an explicit shell executable.

For a write unit, include the relevant writable/protected paths and approval constraints exposed by the current host, or mark them unknown. A registered project, changed cwd, readable source, or user approval in chat does not by itself establish tool permission for a separate worktree. Use the available permission context; do not add a write probe or request broader access merely to qualify delegation. When a known boundary would block the write, choose its owner before dispatch: Main can retain the protected mutation and delegate useful read-only evidence or preparation in an allowed task location, or the worker can own the exact required approval request. Main still needs its own valid tool permission; this split cannot bypass an approval.

Reference original files and the [result contract](#result-contract) instead of copying their full contents or the whole conversation. Pass that contract to independent workers that do not inherit it; keep protocol-specific instructions in the selected lane. Do not omit constraints to shorten the packet. Return concise findings and evidence locations instead of full logs. No new packet files, telemetry, orchestration layer, or test framework is required.

Read [native execution](luna-lane.md) only for a native child. Include the selected lane's startup and return instructions. When reusing a child after relevant execution instructions change, pass the changed instructions with the next handoff; do not assume the child reloads edited files. Preserve the native lane's capacity constraints. The host's current parallel-work requirements still apply; when it permits serial offloading, lack of parallel Main work alone is not a reason to reject it. Qwen's existing synchronous route remains available. Start only ready units; dependencies must finish first.

### Scope mixed tasks by their next ready unit

Useful boundaries include an existing failed-case subset while Main analyzes a different cause; one upstream subsystem while Main compares another; or a fixed artifact/trace inventory while Main handles account access or final acceptance. Require original references and a bounded check, not a new full project survey. Evidence about article claims or retention value can be delegated; rights approval, policy adoption and deletion remain with Main.

A blocked UI action does not block an independent local evidence unit, but delegation cannot reproduce an inaccessible screen, unlock a device or override denied permission. Keep a brief release lookup, small date calculation, wait for an existing review, or quota-bound sequential generation on its existing path when handoff would add work. These are examples of the owner criteria, not a dispatch checklist or required fan-out.

For repeated collection or review under unchanged criteria, give a compatible worker one bounded set of ready inputs and let it chunk internally within source and output limits. Main need not redispatch each chunk; do not wait for future inputs or expand an open-ended scope to fill a batch.

Return coverage, exclusions, source-linked findings and unresolved items for that set at completion or a material blocker. Surface evidence conflicts or decisions requiring Main promptly; keep routine progress non-blocking. Return earlier for user deadlines, execution limits or unreliable/truncated output. Scope new inputs or changed criteria separately. Main verifies coverage and consequential claims before acceptance.

Once assigned, let the worker own implementation, related checks, and ordinary local corrections. Main advances independent work or uses a supported bounded wait; it does not solve the same unit, run its commands one by one, or poll unchanged state repeatedly. Honor explicit user/host call budgets and cancellation limits. Follow the native lane's patient-wait guidance; elapsed time, silence, or a wait timeout alone is not execution failure.

If the user requirement or relevant source changes materially, do not integrate stale output. End or safely interrupt that exact execution and attribute its effects before revalidating or discarding it. Additive guidance that preserves the outcome does not automatically invalidate the unit.

## Accept results and converge

Main inspects the actual diff/artifact and directly affected dependencies, owned scope, requested behavior, and real verification evidence. A worker's summary or self-reported model identity is not proof. Expected test values must follow the requirement or existing contract; never accept weakened tests or circular implementation-derived expectations.

Reuse reliable checks for unchanged code and environment. Repeat only for changed inputs/integration state, a concrete gap, unreliable evidence, or required authority. Accept the actual artifact and the evidence in the result contract below; worker execution completion is separate from Main quality acceptance.

Normal compile/test corrections within a running unit belong to the worker. For compiled-code changes, use the smallest relevant compile/type check before returning an implementation as verified; formatting or parsing alone is insufficient. If the build is centrally owned, unavailable or approval-blocked, return that precise unverified boundary so Main can perform the existing integration check once. Do not add a duplicate full build or transfer ordinary corrections early merely to finish the worker turn. Return control when meaning needs a new decision, the same failure repeats without progress, or an execution limit is reached.

For native workers, retrieve actual artifacts before treating a terse or malformed final message as implementation failure. After the current execution has ended and its effects are attributed, Main may send a clear, localized defect and the existing acceptance check to the same compatible worker when the contract is unchanged and correction plus review is cheaper than takeover. Use the lane's supported follow-up, preserve prior failure evidence, and count correction usage. Misunderstood requirements, repeated same-cause failure without progress, an unrecoverable execution fault, or an execution limit returns ownership to Main under the lane's safe-transfer rules; do not create a retry chain across workers or models. Approval waiting is not a completed failed attempt.

After a failed, invalid, ambiguous, or incomplete Qwen result, confirm execution ended, attribute partial changes and preserve user changes, then return to the existing native/Main path under its normal ownership and scheduling rules. Do not retry the same objective through Qwen, rename it, raise its reasoning effort, or attach a Qwen critic to rescue it. This is a direct return to normal work, not a multi-worker retry chain. This Qwen no-retry rule remains separate from native correction. If attribution is unsafe, stop.

After a native spawn is rejected by capacity/model/surface availability, do not repeat it. Inspect `list_agents` at most once if useful; reuse only an exactly compatible idle non-root child via supported `followup_task`, otherwise Main owns the unit. Do not infer a slot leak or create a new task/fork to evade the limit. Reuse an unresolved common execution failure for affected units until evidence changes.

Use independent review only when requested or justified by consequence, conflicting evidence, or a material validation gap. Keep consequential final criticism with Main. For a specifically justified, cheap, non-final Qwen evidence check, read [Qwen critic](qwen-critic.md); it is not a routine stage, and Qwen never reviews its own candidate. Otherwise Main reviews unless independence is an explicit acceptance condition; report unavailable independent review honestly.

## Result contract

Use the selected lane's completion channel: native final/report to the actual parent handle, or the local adapter's documented result and actual files for Main's retrieval. Do not invent submit_result/escalate tools, send unsolicited cross-task messages, or create a separate report file unless that artifact was requested. This is a meaning contract for the existing return format, not a new schema or required prose template.

- Identify the project, task/session/request or native handle and input revision actually used. If a host identity is unavailable, say so; never substitute the most recent task.
- Distinguish completed, partial, failed, cancelled, and blocked execution. Return material findings, actual changed_paths (empty for read-only work), and the requested artifacts. Completion of a tool, process, or worker turn does not establish product correctness or Main acceptance.
- Give each material evidence reference its source location, existing revision or observed modification state, and the range actually read. Mark omissions, truncation, inaccessible sources, and unverified claims. Partial reading remains partial.
- For checks, report command, cwd, scope, passed/failed/not_run, executed_here/reused_prior, evidence reference and valid_for_revision. Reused evidence needs unchanged relevant inputs, environment and acceptance criteria. Never relabel it as executed_here or describe a targeted check as the requested full suite. A not_run check has no execution evidence.
- Keep failures and unique counterexamples in the returned evidence. For bounded listings distinguish total count from shown count; reference readable raw output when preserved, and disclose preservation/readback failure instead of claiming a source exists.

Keep cancellation, approval waiting, provider error, process loss, and supersession distinct. Do not revive a user-cancelled unit or accept duplicate/late output for a different request or revision. After disconnection, reconcile the original execution and partial changes before any new dispatch; in-memory handles alone do not prove restart recovery. Continue independent authorized work after a failure, but require successful prerequisites before dependent effects. Recheck permission against final arguments when the target or arguments change after approval. These are host/evidence decisions, not semantic-model scores.
