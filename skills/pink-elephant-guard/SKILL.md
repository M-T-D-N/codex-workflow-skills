# Pink Elephant Guard

폐기된 과거안을 다시 언급하지 않고 현재 확정 상태만으로 사용자 대면 최종 산출물을 재구성한다. 일반적인 요약, 기억 관리, 도메인 편집을 대신하지 않는다.

## 적용 조건

다음 조건을 모두 만족할 때 사용한다.

1. 현재 대화나 허용된 회수 문맥에 폐기·삭제·정정된 개념이 있다.
2. 사용자가 독자·고객·사용자에게 바로 제시할 최종 산출물을 원한다.
3. 변경 이력이나 과거안 비교가 결과에 필요하지 않다.

다음에는 사용하지 않는다.

- 과거안 비교, 감사, 디버깅, 원인 분석, handoff, 변경 로그
- 마이그레이션, 하위 호환성, 규정·안전 고지처럼 과거 상태나 경고가 필요한 작업
- 현재 확정 상태가 충돌하거나 결과를 바꿀 정도로 미해결인 작업
- 과거 기록 정리, 기억 삭제 또는 재분류
- 일반 코드 변경. 단, 사용자가 변경 이력 없는 최종 재구현을 명시했고 과거 상태가 계약·테스트·마이그레이션에 필요하지 않은 경우는 예외로 한다.

## 현재 상태 확정

현재 사용자의 요청과 적용되는 최신 authority를 우선한다. 회수된 기억과 과거 대화는 후보 문맥일 뿐 현재 근거보다 우선하지 않는다.

현재 상태가 실질적으로 충돌하면 조용히 병합하지 않는다. 허용된 현재 근거를 먼저 확인하고, 결과를 바꾸는 불확실성이 남을 때만 한 가지 핵심 질문을 한다.

작업 중에만 다음 네 범주를 구분한다. 별도 파일이나 영속 기록은 만들지 않는다.

- `TARGET_STATE`: 현재 확정된 요구와 사실
- `REJECTED_HISTORY`: 폐기·삭제·정정된 문구, 논리, 구조, 라벨, 프롬프트
- `VISIBLE_EXCEPTIONS`: 안전·법률·계약·접근성·사실 정확성을 위해 반드시 보여야 하는 내용
- `SURFACE`: 사용자가 보게 될 최종 산출물 전체

## 재구성 절차

1. `TARGET_STATE`의 필수 내용만 긍정형으로 정리한 임시 Clean Brief를 만든다.
2. “과거 X를 넣지 않는다”처럼 폐기안을 되뇌는 지시 대신 현재 상태 자체를 명시한다.
3. Clean Brief에서 오염된 `SURFACE` 부분을 새로 구성한다. 현재 확정된 비오염 내용은 보존하고, 변경 범위는 사용자 요청과 도메인 스킬의 편집 경계를 따른다. 폐기안을 부분 수정한 문장을 출발점으로 삼지 않는다.
4. 결과를 한 번 점검해 다음 누출을 찾는다.
   - 과거안의 직접 문구와 동의 표현
   - 과거안에만 필요한 이유·주의 환기·비교 구도
   - 삭제된 구획, 라벨, 자리표시자, 프롬프트 구조
   - 실제 미디어를 검사한 경우에만 적용되는 시각·청각 흔적
5. 누출이 있으면 오염된 초안을 전달하지 말고 Clean Brief에서 해당 부분을 한 번 재구성한다. 새 근거 없이 검사를 반복하지 않는다.

필수 안전·법률·계약·접근성 고지와 사용자가 명시적으로 요구한 예외는 숨기지 않는다. 이때 필요한 현재 고지만 남기고 불필요한 과거 서사는 덧붙이지 않는다.

## 다른 스킬과의 경계

- 문서·이미지·프레젠테이션·소설 편집 등 도메인 스킬이 내용과 매체 품질을 소유한다.
- 이 스킬은 그 결과 표면에서 `REJECTED_HISTORY`가 되살아나는지만 통제한다.
- 과거 맥락은 실제로 필요하고 사용자가 허용한 기록이 있을 때만 회수한다. 별도 기억 서비스는 필수 조건이 아니며 이 스킬은 기억을 쓰거나 삭제하지 않는다.
- `prepare-codex-handoff`처럼 변경 이력과 복구 맥락이 핵심인 작업에는 이 스킬을 적용하지 않는다.

## 부작용 금지

- 기억 쓰기·삭제·재분류를 하지 않는다.
- Clean Brief나 점검표를 파일로 남기지 않는다.
- 새 task, fork, subagent를 만들지 않는다.
- 외부 전송을 하지 않는다.
- 사용자가 이미 요청한 최종 산출물 외의 파일이나 상태를 변경하지 않는다.
